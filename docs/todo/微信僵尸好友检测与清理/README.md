## 1. 一句话结论

两阶段主动任务：**阶段一（检测）**自动建 30 人小群 → 读取微信返回的"无法邀请/拒绝加入"系统消息 → 解析归属（已删除/被拉黑/封禁）→ 自动退群，循环直至全部好友检完；**阶段二（清理）**结果列表勾选 → 确认弹窗 → 逐条搜索/校验/删除选中好友（幂等、断点、失败快照）。前置检查含**空树预检（C-205）**：微信按服务组件类名白名单发树，依赖基座伪装类名（D-011/D-212），空树会导致全流程失效。当前 `todo`，等待基座编排器就绪后从 T-001 开始。

### 3.2 目标调用链

```text
用户点击"开始检测" → WeChatFeature 前置检查 → [基座]OpenApp(com.tencent.mm)
  -> TaskOrchestrator.run(WechatZombieTask)
  -> 循环批次: [主界面→+→发起群聊→勾选30人(滚动/去重)→创建]
       -> 读系统消息(无法邀请/拒绝加入/违规) → 解析名单 → 持久化
       -> 聊天信息→滑动→删除并退出→确认 → 回到主界面
  -> 全部完成 → 结果页 → (可选)CSV 导出
```

关键约束：

1. 不发送任何聊天消息、不进入转账/付款界面。
2. 批次默认 30（<40 阈值的保守值），可配。
3. 任务执行期间，同包规则点击由基座互斥让位（任务优先）。
4. 一切文案以"包含匹配"实现，微信改版时优先保流程可达性。

## 6. 数据模型 / 配置 / 接口

### 6.1 数据模型

```kotlin
enum class ZombieKind { DELETED, BLOCKED, BANNED }

@Entity(tableName = "wechat_zombie_scan")
data class ZombieRecord(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    val runId: String,           // 本轮检测会话 ID
    val nickname: String,        // 消息中的昵称（微信系统消息原文）
    val kind: ZombieKind,
    val rawMessage: String,      // 原始系统消息（证据）
    val scannedAt: Long,
)

data class ScanCheckpoint(        // 断点（DataStore）
    val runId: String,
    val processedCount: Int,
    val lastBatchNames: List<String>,  // 上批已处理名单（去重基准）
)
```

### 6.2 配置项

| 配置项 | 默认值 | 行为 | 兼容性 |
|---|---|---|---|
| `wechat.batchSize` | `30` | 每群勾选人数（20~39） | 新增 |
| `wechat.dryRun` | `false` | 仅检测不删群 | 新增 |
| `wechat.keepHud` | `true` | 显示进度浮层 | 新增 |
| `wechat.scanTimeoutMs` | `900000`（15min） | 会话级超时 | 新增 |
| `wechat.delete.defaultSelection` | `deletedOnly` | 弹窗预选范围（`deletedOnly`=仅"已删除你"类；`all`=三类全选；`none`） | 新增 |
| `wechat.delete.withHistory` | `false` | 删除时是否同时删除聊天记录（false=保留） | 新增 |
| `wechat.delete.verifyName` | `true` | 资料页名称二次校验（防重名误删） | 新增 |
