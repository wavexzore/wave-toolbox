## 1. 实施结论

"拉群法"是微信生态里被验证十五年的零打扰批量检测方式：建 <40 人小群时对方无通知，微信自身会在群里给出"你无法邀请未添加你为好友的用户…"等三类系统消息，准确且无需发消息、无需付款。`wlj32011/InspectWechatFriend`（2016）已用无障碍服务完整跑通该流程（300 好友 3 分钟），但其实现为硬编码 `Thread.sleep` + Activity 类名直达 + 版本 view-id 表，可维护性差。

本计划用基座 TaskOrchestrator 重写为**事件驱动的 Step 状态机**（两阶段）：**阶段一检测**——文本锚点优先（抗 view-id 漂移）、批次保守（默认 30）、结果三类解析、自动退群、断点恢复、进度 HUD、失败即快照；**阶段二清理**——结果列表勾选 → 确认弹窗 → 逐条搜索/资料页校验/删除选中（幂等、断点、快照）。

最小安全切片：阶段一 T-001→T-004（能检测出第一份名单）→T-005（能干净退群）→T-010（真机检测验收）；阶段二 T-011（列表多选+弹窗）→T-012（删除执行）→T-013（真机删除验收：识别后列出列表→弹窗选择→点击删除→删除选中用户）。

明确不做：消息群发、转账复检、自动加回（见 §5.3）。LLM 从 T-001 开始；引擎级缺口回写基座计划。

## 4. 目标方案

### 4.1 目标链路

```text
[基座]OpenApp(com.tencent.mm) → WaitFor(主界面锚点"通讯录/微信"tab 或 desc"更多功能按钮")
  -> 批次循环 {
       Click(desc~"更多") → WaitFor("发起群聊") → Click
       -> WaitFor("选择联系人") → SelectContacts(30, 文本优先/滚动/去重)
       -> Click(["完成","确定"] 含数字) → WaitFor(聊天页系统消息)
       -> ReadText(消息: 无法邀请|拒绝加入|违反用户行为规范) → 解析 → 持久化
       -> Click("聊天信息"|desc"…") → Scroll 到底 → Click("删除并退出")
       -> WaitFor("离开群聊"|"删除并退出") → Click → WaitFor 主界面
     }
  -> 全部完成 → 结果列表（三类分区/可勾选/已清理标记）→ (可选)CSV 导出
  -> 用户勾选选中集 → 确认弹窗(数量+聊天记录选项) → 基座任务: DeleteFriendsTask  // 阶段二
       -> 逐条: 通讯录搜索显示名 → 打开资料页 → 名称二次校验 → "…"→删除→处理对话框 → 返回
       -> 成功置"已清理"；失败留快照可重试；HUD 显示删除进度 n/m          // 幂等+断点
  -> 结束汇总（成功/跳过/失败）
```

### 4.2 设计决策

| D-ID | 决策 | 理由 | 拒绝方案 | 影响任务 |
|---|---|---|---|---|
| D-201 | 拉群法为主，批量默认 30 | <40 无扰的保守值；每批 30 提高效率 | 10 人批（更保守但群数×3） | T-003 |
| D-202 | 文本包含匹配为第一锚点，类名刻意降级为提示 | 微信类名/view-id 漂移频繁 | 纯 view-id（2016 教训） | T-002 |
| D-203 | 选择列表用"可见昵称集合稳定哈希 ×2 连续不变"判尾 | 替代不可靠的 rowCount 近似 | rowCount（悬浮"已选"区干扰） | T-003 |
| D-204 | 三解析器只认锚点短语，名字用分隔符切分且保留原文 | 抗版本漂移；原文可审计 | 全句正则（漂移即碎） | T-004 |
| D-205 | 断点以"已处理昵称集合"而非索引 | 列表顺序随选中重排 | 索引游标 | T-004 |

| D-207 | 默认执行"删除并退出"；提供 dry-run | 群留着会打扰用户 | 只检不删 | T-007 |
| D-208 | 会话级看门狗（单步超时 + 会话超时 15min，可配） | 防挂死 | 无超时 | T-008 |

| D-210 | 幂等双保险：记录状态（已清理标记）+ 资料页形态信号（"添加到通讯录"=已非好友） | 二次运行安全、可断点续删 | 仅靠记录状态 | T-012 |
| D-211 | 默认保留聊天记录；确认弹窗提供"同时删除聊天记录"开关；对话框复选框缺失时按默认继续 | 不可逆项默认温和 | 强制删除记录 | T-011,T-012 |
| D-212 | 依赖基座 D-011 服务组件伪装类名（冻结）；每轮真机任务前跑 C-205 空树预检；空树出现时先核对组件全限定名再排查锚点 | 微信空树门禁是硬前提（ledger 实证） | 自有类名（微信空树） | T-001,T-002 |
